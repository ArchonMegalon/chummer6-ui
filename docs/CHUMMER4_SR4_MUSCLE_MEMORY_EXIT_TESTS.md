# Chummer4 / SR4 Muscle-Memory Exit Tests

Core rule: when the promoted SR4 desktop lane exposes a function that Chummer4 already had, the promoted surface should keep the same mouse-first control posture and naming.

This gate is narrower than the Chummer5A main-editor gate because SR4 is still an import-tools-first lane, but it is still fail-closing for the SR4 surfaces we do promote:

- switch-ruleset chooser
- SR4 new-character chooser
- SR4 starter-runner follow-through
- SR4 gear-selection posture
- Chummer4-backed shared utility dialogs such as Dice Roller
- the full promoted SR4 dialog/panel/menu/tooltip surface inventory once an SR4 runner is live

The gate layers are:

1. Promoted SR4 scope review
- The policy must explicitly state that it is about promoted SR4 surfaces backed by Chummer4 dialog oracles.
- Chummer4 as the legacy oracle must be named directly in the design copy so the scope cannot silently drift back to a generic SR4 posture.
- The gate must also require the existing SR4 workflow parity receipt to be passing so the muscle-memory slice cannot float free from the broader SR4 frontier proof.

2. Dialog-oracle review
- Chummer4 WinForms designers remain the oracle for widget class and visible copy on matching dialogs.
- The current source must keep the same combo-box and compact-dialog posture where the same function still exists.

3. Runtime replay review
- A runtime inventory receipt must loop through every promoted SR4 dialog, panel, grid, menu root, and tooltip-bearing control after an SR4 runner is loaded.
- Runtime-backed tests must prove the promoted SR4 lane still mounts combo-based choosers instead of freeform text boxes.
- The seeded runtime checks cover the SR4 switch-ruleset chooser, SR4 new-character build-method chooser, SR4 starter-runner gear category chooser, and the shared Dice Roller utility.
- The runtime layer must also fail when row order, footer placement, two-pane geography, or spinner posture drift away from Chummer4 muscle memory.
- The runtime inventory must also fail when left/right slot ownership, within-slot field order, or right-click secondary-menu posture drift away from the legacy dialog rhythm.
- Chummer4 spinner-class controls should stay spinner-class controls when the same utility lane still exists.
- The new-character chooser must keep the Modify button on the build-method row and keep the OK/Cancel footer on one compact legacy action band.
- The SR4 gear selector must keep the browse list on the left, details on the right, and the commit buttons on one legacy action band.

4. Verify wiring review
- The gate must run from `scripts/ai/verify.sh` so SR4 muscle-memory drift fails the standard exit path.
