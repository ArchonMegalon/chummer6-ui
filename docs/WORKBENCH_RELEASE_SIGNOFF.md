## Extended Goal Release Blockers

The broadened Blazor goal cannot be signed off as a polished web-delivered desktop client until the runtime proof refresh is complete. The current source-staged and source-plan receipts are allowed to guide the work, but they are not release evidence.

Release promotion is blocked until generated receipts are refreshed after the /app route, portal handoff, Rybbit, roster hierarchy, Runner Intelligence, and slate/amber/mint/blue theme changes. The refreshed proof set must include source-staged receipts, source-plan receipts, source-calculation receipts, hosted route-entry receipts, hosted execution receipts, Docker self-host receipts, and the aggregate browser-lane receipt.

The browser release claim must keep hosted route-entry, hosted execution, Docker self-host, and aggregate browser-lane receipts separate. `/app` is the clean public Chummer Online route, `/blazor/app` is the hosted app path, and `/blazor/workbench` remains the explicit proof-compatible workflow execution lane.

Runner Intelligence and roster hierarchy remain source/staged until runtime proof covers the actual browser and self-host flows. Runner Intelligence must prove reusable `Chummer.Presentation` calculation seams for Avalonia and Blazor before percentile, spell/drug/gear what-if, or cohort-statistics claims are promoted. Roster hierarchy must prove runtime drag/drop or keyboard move execution, durable persistence, safe delete/reparent behavior, and non-destructive filesystem policy before it becomes a release workflow claim.

Rybbit remains metadata-only and self-host default-off. Release proof must keep session replay disabled, autocapture disabled, sensitive character/workspace/file data excluded, and hosted/self-host analytics posture visible in the health/status lanes.

The aggregate browser-lane proof set may require `BLAZOR_SOURCE_STAGED_RELEASE_BOUNDARY.generated.json` as source-policy input, but that guard only proves source-staged, source-plan, and source-calculation receipts stayed out of release-readiness aggregation. It must not be treated as hosted workflow execution, Docker workflow execution, parity breadth, or polished-product proof.

Those lines confirm whether the regenerated aggregate receipt carries the source-policy-only guard note and the `MIG-106` through `MIG-109` open-until-refreshed-proof posture.

The slate/amber/mint/blue visual treatment must stay consistent across Blazor app chrome, public home, portal recovery pages, downloads/install handoff, docs explorer, and native installer progress surfaces before polish language is promoted.

Do not use source-staged receipts as release evidence. Do not use source-plan receipts as release evidence. Do not use source-calculation receipts as hosted, Docker, or aggregate browser-lane proof.
